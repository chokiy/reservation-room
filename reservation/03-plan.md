# 03. 구현 계획 — 회의실 예약 앱

기준 문서: `01-requirements.md`, `02-flow-design.md`, `mockups/index.html`(화면 참고용 정적 목업)

## 기술 구조

| 영역 | 선택 |
|---|---|
| 프레임워크 | Next.js (App Router) + TypeScript |
| 스타일 | Tailwind CSS (목업의 남색 포인트·초록/주황 상태색을 따름) |
| DB | Supabase Postgres |
| 인증 | Supabase Auth 이메일/비밀번호 (OAuth 없음, 이메일 인증 끔) (가정) |
| 데이터 접근 | `@supabase/supabase-js` + `@supabase/ssr`, 서버 컴포넌트·서버 액션 |
| 권한 | Postgres RLS가 최종 방어선, 서버 액션에서는 사용자 친화적인 에러 메시지 처리 |
| 배포 | Vercel (환경변수: Supabase URL, anon key) |
| 테스트 | Vitest (슬롯·시간 변환, 겹침·권한 판정 같은 순수 함수) |

### 폴더 구조 (디렉터리 수준)
```
reservation_room/
├─ reservation/          # 기획 문서 (이미 있음)
├─ app/                  # 라우트: (auth) 로그인·가입, 메인 그리드, my
├─ components/           # grid, reservation-modal, now-band 등
├─ lib/                  # supabase 클라이언트, 시간·슬롯 유틸, 서버 액션
├─ supabase/             # migrations (스키마·RLS·시드 SQL)
└─ tests/
```
앱은 `reservation_room/` 루트에 `create-next-app`으로 만든다. 기획 문서 폴더(`reservation/`)는 그대로 둔다.

### 스키마 (테이블 5개라 필요)
```sql
teams(id, name)                                   -- 시드: 팀 목록
profiles(id = auth.users.id, nickname, team_id, fstrgdt)  -- 가입 시 트리거로 생성
                                                  -- fstrgdt = 최초 등록 일시, 비밀번호(pw)는 auth.users에 해시로 저장(profiles에는 두지 않음)
rooms(id, name)                                   -- 시드: 회의실1~10
reservations(id, room_id, date, start_slot, end_slot,  -- 슬롯 0~17, end는 배타(1~18)
             title, created_by, team_id, created_at, updated_at)
reservation_attendees(reservation_id, user_id)

-- 겹침 방지(동시 요청 포함): btree_gist 확장
EXCLUDE USING gist (room_id WITH =, date WITH =, int4range(start_slot, end_slot) WITH &&)
CHECK (start_slot >= 0 AND end_slot <= 18 AND start_slot < end_slot)
```
슬롯 변환: `slot i` ↔ `08:00 + 30분 × i`.

### 권한 규칙 (RLS)
| 동작 | 허용 대상 |
|---|---|
| 조회 | 로그인한 모든 사용자 |
| 생성 | 로그인 사용자 (`team_id`는 본인 팀, 화면 표시용이며 권한 판정에는 쓰지 않음) |
| 수정 | 예약자 또는 참석자 |
| 취소(삭제) | 예약자 또는 참석자 (수정과 동일) |
| 참석자 추가/삭제 | 해당 예약을 수정할 수 있는 사람 |

## M1 — 프로젝트 셋업 + DB (30~40분)

**목표**: 앱이 로컬에서 뜨고, Supabase에 스키마와 시드가 들어간 상태로 만든다.

**할 일**
- [ ] `create-next-app`(TS, Tailwind, App Router)로 루트에 생성, Vitest 설정
- [ ] Supabase 프로젝트 연결: `.env.local`, `.env.example` (URL·anon key)
- [ ] `supabase/migrations`: 테이블, 겹침 제약, RLS, 가입 트리거(`profiles` 생성), 시드(회의실1~10, 팀)
- [ ] `lib/`에 서버·브라우저 Supabase 클라이언트, 슬롯↔시간 유틸 + 단위 테스트

**완료 조건**
- [ ] `npm run dev`로 기본 페이지가 열린다
- [ ] Supabase 대시보드에서 `rooms` 10행, `teams` 시드가 보인다
- [ ] 같은 방·날짜에 겹치는 `reservations` 두 행을 SQL로 넣으면 두 번째가 거부된다

**검증 방법**
- [ ] 자동: `npm test`(슬롯 변환), `npm run build`
- [ ] 수동: Supabase 대시보드에서 시드와 제약 확인

**중단 가능 지점**: 여기까지면 DB 기반만 있는 상태. 화면은 없다.

> **필요한 것**: M1 시작 때 Supabase 프로젝트 URL과 anon key가 필요합니다. 프로젝트가 없으면 만드는 방법부터 안내드립니다. 팀 목록(실제 팀 이름)도 이때 받습니다.

## M2 — 인증 (30~40분)

**목표**: 이메일·비밀번호로 가입·로그인하고, 로그인해야만 메인에 들어갈 수 있다.

**할 일**
- [ ] `/signup`(이메일·비밀번호·닉네임·팀: 목록에서 선택, 없으면 "새 팀 직접 입력". 가입 metadata로 `team_id` 또는 `team_name` 전달), `/login`, 로그아웃
- [ ] Supabase Auth 세션 처리(`@supabase/ssr`), 비로그인 접근 시 `/login`으로 이동
- [ ] 헤더에 "이름 (팀)" 표시

**완료 조건**
- [ ] 가입하면 `profiles`에 닉네임·팀·최초 등록 일시(fstrgdt)가 저장된다
- [ ] 로그아웃 후 `/` 접근 시 로그인 화면으로 간다

**검증 방법**
- [ ] 자동: 입력 검증 함수 테스트, `npm run build`
- [ ] 수동: 가입 → 로그인 → 새로고침 후 유지 → 로그아웃

**중단 가능 지점**: 로그인 가능한 빈 앱.

## M3 — 현황 그리드 (읽기) + 지금 상태 (40~50분)

**목표**: 선택한 날짜의 회의실 × 시간 현황을 목업과 같은 모양으로 읽기 전용으로 보여준다.

**할 일**
- [ ] 그리드 컴포넌트: 가로 = 08:00~17:00 30분 칸 18개, 세로 = 방 10개, 방 이름 열 고정, 예약 블록(팀 색 + 제목 + 팀명)
- [ ] 날짜 바: ◀ ▶, 오늘, 날짜 선택(URL 쿼리로 날짜 유지)
- [ ] 현재 시각 세로선, 지난 칸 회색 (오늘/과거 날짜 구분)
- [ ] **(차별점) "지금 비어있는 방" 띠**: 오늘 화면 상단에 현재 비어 있는 방을 칩으로, 사용 중인 방은 행 앞에 주황 점 + 예약 팀 표시. 오늘이 아닌 날짜에서는 안내 문구로 대체
- [ ] 임시 예약 몇 건을 SQL로 넣어 확인

**완료 조건**
- [ ] 날짜를 바꾸면 그 날짜의 예약이 정확한 칸에 그려진다
- [ ] **(차별점 반영)** 오늘 화면에서 현재 비어 있는 방과 사용 중인 방이 한눈에 구분된다. 현재 시각 기준으로 갱신된다(새로고침/1분 주기)
- [ ] 한 일의 시간 → 칸 위치 계산이 슬롯 유틸과 일치한다

**검증 방법**
- [ ] 자동: 블록 위치/폭 계산, "지금 사용 중" 판정 단위 테스트, `npm run build`
- [ ] 수동: S1 앞부분(날짜 이동 후 빈 방 찾기), S2 앞부분("지금 비어있는 방" 띠)

**중단 가능 지점**: 예약 현황을 볼 수만 있는 조회용 앱.

## M4 — 예약 생성 (40~50분)

**목표**: 빈 칸을 골라 제목·참석자를 입력하고 [예약]을 누르면 저장되어 그리드에 나타난다.

**할 일**
- [ ] 칸 클릭·드래그 선택(연속 슬롯), 모달 열기
- [ ] 예약 모달: 방·날짜·시작·종료 드롭다운, 제목, 참석자 검색 선택(1명 이상)
- [ ] 입력 검증: 제목·참석자 필수(비면 [예약] 비활성화), 종료 > 시작, 지난 시간 불가
- [ ] 서버 액션: 예약 + 참석자 저장, DB 겹침 제약 위반 시 "방금 예약되었습니다. 다른 시간을 선택하세요" 표시
- [ ] **(차별점 연결)** "지금 비어있는 방" 칩 → 모달이 가장 가까운 30분으로 미리 채워진 채 열림

**완료 조건**
- [ ] [예약] 버튼을 눌러야만 저장된다(닫으면 아무것도 저장되지 않는다)
- [ ] 같은 방·시간에 두 번째 예약은 거부되고 이유가 보인다
- [ ] 참석자가 다른 팀 사용자여도 지정된다

**검증 방법**
- [ ] 자동: 검증 함수, 겹침 판정 테스트, `npm run build`
- [ ] 수동: S1 전체, S2 1~3단계. 브라우저 두 개로 같은 칸을 동시에 예약해 한쪽이 거부되는지 확인

**중단 가능 지점**: 예약 조회·생성만 되는 앱. 수정·취소 없이도 사용은 가능.

## M5 — 예약 수정·취소 (35~45분)

**목표**: 예약을 열어 권한에 맞게 수정하거나 취소한다.

**할 일**
- [ ] 예약 블록 클릭 → 상세 보기(제목, 팀, 예약자, 참석자, 시간)
- [ ] 수정 모드(생성 모달 재사용): 제목·참석자·시간·방 변경, **[수정] 버튼**을 눌러야 반영, 닫으면 변경 버림, 수정 후에도 겹침 검사
- [ ] 취소: 예약자와 참석자에게만 [취소] 버튼 표시, 확인 대화상자 후 삭제
- [ ] 권한 없는 사용자에게는 버튼을 숨기고, DB(RLS)에서도 막힘

**완료 조건**
- [ ] 예약자와 참석자만 [수정]·[취소]가 보이고 동작한다
- [ ] 같은 팀이어도 예약자·참석자가 아니면 [수정]·[취소]가 보이지 않고 DB에서도 거부된다
- [ ] 수정으로 참석자에서 빠진 사람은 그 즉시 권한을 잃는다
- [ ] 수정 중 [닫기]하면 원래 내용이 유지된다

**검증 방법**
- [ ] 자동: 권한 판정 함수 테스트, `npm run build`
- [ ] 수동: S2 4단계. 계정 3개(예약자, 참석자, 같은 팀이지만 참석자 아닌 사람)로 버튼 노출과 동작 확인

**중단 가능 지점**: 핵심 기능이 모두 있는 완성본. M6·M7은 마감 단계.

**할 일**

**완료 조건**
- [ ] 모바일 뷰포트에서 페이지 전체가 가로로 흔들리지 않고, 그리드만 스크롤된다
- [ ] 모바일에서 S2 전체 흐름이 가능하다

**검증 방법**
- [ ] 자동: `npm run build`, lint

## (가정) 누적 목록
- 메인은 가로 시간축 × 세로 회의실 그리드, 날짜는 상단 날짜 바 (+ "지금 비어있는 방" 띠)
- 팀은 목록에서 선택하거나 새 팀 이름 직접 입력 (새 팀은 가입 트리거가 생성, 이름 30자 이내, 대소문자·공백 무시 중복 방지)
- 지난 시간·날짜는 예약 불가
- 수정·취소 권한은 모두 예약자 + 참석자 (팀 단위 권한 없음)
- 참석자는 가입한 사용자만, 1명 이상 필수
