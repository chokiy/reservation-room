# 01. 요구사항 — 회의실 예약 앱

## 한 줄 정의
우리 회사 여러 팀이 10개 회의실의 빈 시간·예약 현황을 한눈에 보고, 원하는 방을 30분 단위로 예약·취소하는 사내 웹앱.

## 핵심 문제
- 어느 방이 비었는지 알려면 일일이 물어보거나 확인해야 한다.
- 여러 팀이 같은 방을 중복 예약하는 일이 생긴다.

## 주 사용자와 사용 상황
- 사내 각 팀 구성원. 예약 권한은 팀이 아니라 예약자·참석자 기준이다.
- 하루 여러 번 사용 (출근 직후 당일 예약, 회의 직전 빈 방 찾기).
- 데스크톱(자리)과 모바일(회의실 앞)을 모두 사용한다. (가정)

## 고정 조건
- 회의실 10개: 이름은 `회의실1` ~ `회의실10`. 이름 외 정보(인원·층·장비)는 없다.
- 예약 가능 시간: 08:00~17:00, 30분 단위 슬롯 (총 18슬롯/일).
- 같은 방에서 시간이 겹치는 예약은 불가.

## MVP 핵심 기능
1. **로그인/회원가입**: 이메일 + 비밀번호 (자체 구현). OAuth는 쓰지 않는다.
2. **팀 소속**: 가입 시 팀 목록에서 선택하고, 목록에 없으면 새 팀 이름을 직접 입력해 만든다. (대소문자·공백만 다른 같은 이름은 기존 팀으로 합친다.)
3. **현황 화면**: 회의실 × 시간 그리드. 각 칸에 **빈 시간 / 예약됨(예약 팀 표시)** 을 구분해서 보여준다. (가정: 그리드 형태)
4. **예약 생성**: 빈 칸을 선택해 방·날짜·시작~종료 시각·**회의 제목·참석자**로 예약한다. 참석자는 가입한 사내 사용자 중에서 지정한다(다른 팀도 가능). 연속된 여러 슬롯을 한 번에 예약할 수 있다.
5. **예약 수정**: **예약자와 지정된 참석자**가 제목·참석자·시간·방을 수정할 수 있다. (수정 후에도 겹침 검사)
6. **예약 취소**: 수정과 같은 권한(**예약자와 지정된 참석자**)으로 취소할 수 있다. 팀 소속은 권한과 무관하다.
7. **날짜 이동**: 오늘 외 다른 날짜(미래)의 현황 조회·예약. 지난 시간은 예약할 수 없다. (가정)

## 사용 우선순위
1순위 **사전 예약**(며칠 전에 날짜를 골라 방을 잡음), 2순위 **즉흥 예약**(지금 빈 방 찾기).

## 차별점 (1줄)
**"지금 이 순간"의 방 상태를 강조한다.** 메인 화면에서 현재 비어 있는 방과 현재 사용 중인 방(예약 팀 포함)을 즉시 구분해 보여준다.

## 데이터 (개략)
- 팀, 사용자 프로필(id·닉네임·팀·최초 등록 일시 fstrgdt. 이메일·비밀번호 해시는 Supabase Auth가 보관), 회의실(이름), 예약(방·날짜·시작·종료·제목·예약자·팀), 예약-참석자(예약·사용자).

## 기술 방향
- Next.js + TypeScript. 배포 계획이 있으므로 파일 기반 SQLite는 쓰지 않는다.
- **데이터 저장: Supabase Postgres (확정, 사용자 지정).**
- 로그인은 이메일 + 비밀번호 방식만 쓰고 OAuth는 쓰지 않는다. Supabase Auth(이메일/비밀번호)를 쓸지 직접 구현할지는 Phase 3에서 확정한다. (가정: Supabase Auth 이메일/비밀번호)
- 겹치는 예약 방지는 DB 제약(시간 범위 겹침 차단)으로 막는다. (가정)

## 범위 제외 (초안, 확인 필요)
- 반복 예약, 캘린더 연동(구글/아웃룩), 알림 메일, 승인 절차
- 비밀번호 재설정/이메일 인증, 관리자 화면(회의실·팀 편집)

## (가정) 목록
- 메인 화면은 회의실 × 시간 그리드
- 팀은 목록에서 선택하거나 새 팀 이름을 직접 입력 (팀 이름 수정·삭제·병합 화면은 없음)
- 지난 시간은 예약 불가
- 수정·취소 권한은 모두 예약자 + 참석자 (팀 단위 권한 없음). 팀은 화면 표시(색·팀명)에만 쓴다.
- 참석자는 가입한 사용자 중에서만 선택 (외부인 불가)
- 반응형 (모바일 포함)
